表 B · 痛点 → 层 → 机制：层1 每个文件都因一个痛点存在

问法：先有痛点，后有机制。这七行就是「为什么会多出这些文件」的答案。

痛点（不解决会怎样） 属于 机制（文件） 一句话原理
主管硬编码六节点 → 加一个子 Agent 就要改主代码、重新发版（原要求：动态发现/自动扫描注册/懒加载/渐进式披露） 层1 plugin_registry.py + agents/ 契约 discover=扫 agents/+plugins/ 自动注册 · AST 元数据=只读说明书不执行 · load_agent=派发才加载 · 丢个文件主管零改动
LLM 输出不确定、要钱、要网络 —— 无法靠「跑一遍」判断改动对错 层1 llm.py + tests/ 桩 接缝把模型从逻辑里抽走；测试把模型换成固定答案的桩，纯逻辑离线断言
模型/网络会挂（429、超时、断网）—— 用户看到 traceback 层1 stability.py 重试（指数退避）→ 熔断（连续失败直接拒绝）→ 兜底（崩了给一句人话）
两个月后看不懂「为什么主管节点是循环生成的」 层1 CONTEXT.md + ADR 决策理由留档；ADR-0003 写明「编排顺序是产品行为，不许改」；ADR-0005 记录「多 Agent 化反转」
交付场景缺 .env / 脏目录 —— 一导入就 KeyError 崩 层1 llm.py + rag.py 懒校验 构造才校验、缺变量一次性报齐；导入无副作用（clean-dir 测试兜底）
一句话两个请求只能串行排队等 层0 graph_builder.py 意图识别拆 subtasks → Send 并行派发 → merge 汇总（fan-out/fan-in，同一注册表）
六个执行节点混在 system.py 里 → 改一个牵动主管图 层0 agents/ 六实体薄壳 每个子 Agent = INTENT + DESCRIPTION + run(state)，实现收口于 trip_planner/memory/rag/web 深模块

67 个测试里 53 个不联网 —— 不是偷懒，是逻辑才是主角，LLM 只是被替换掉的演员。 test_itinerary 里有个 boom()：「如果缺项时调用了生成模型就抛错」——测的是「逻辑不该做的事」，只能靠桩测出来，跑真 LLM 反而测不出。 新增的外部扩展识别（差旅统计）也有 2 条集成用例 + 1 条端到端派发用例——动态词汇表由真模型验证。

副作用：单元测试秒级全跑 → 每次改动敢提交；集成测试只在大改动后跑 → 验证真实模型路径。

表 D · 逐文件速查：这个文件为什么存在

层0 · 运行时（演出）
session.py会话循环收口：读最近对话 → 注入 → invoke → 写回两轮
intent.py意图识别单一来源：词汇表 = 注册表 manifest 动态生成（渐进式披露）+ 多意图拆分 + 指代消解
system.py完整系统总装：discover → set_intents → 注册表驱动建节点/路由（加子 Agent 零改动）
agents/六个内置子 Agent 实体（INTENT + DESCRIPTION + run(state)）：itinerary / preference / history / knowledge / web / other
trip_planner.py行程管线：提取 → 补全 → 缺项 → 生成 → 写回（顺序是产品行为）
memory.py两层记忆：短期消息 + 长期偏好/历史（唯一后端 Postgres）
rag.py知识问答：dashscope embedding + Chroma 向量检索
web.py联网查询：ToolNode ReAct（天气/汇率/空气质量）
reference_data.py领域参考数据单一来源：城市/车次/城市分级/住宿标准
webapp.pyFastAPI 可视化界面（复用 system 完整系统）
层1 · 脚手架（安全感）
llm.py模型单一接缝：懒构造 + 缺变量一次报齐 + 熔断守卫代理
stability.py重试 / 熔断 / 兜底 / 日志 / 健康检查（热路径守卫）
plugin_registry.py子 Agent 注册中心：discover（agents/+plugins/）/ AST 元数据 / load_agent 懒加载 / 内置优先
plugins/stats.py外部扩展子 Agent：差旅统计（第七意图，真实路由；演示动态发现）
tests/53 单元（桩替换 LLM）+ 14 集成（真 LLM）= 67 全过
CONTEXT.md领域术语表：主管/子 Agent/注册中心/意图/常驻城市/缺项提示…
docs/adr/ADR-0001..0005：接缝/会话/行程/插件边界（多 Agent 化反转）/ RAG 保持现状
demos/plugin_demo（发现/懒加载/热插拔/外部扩展真实路由）+ stability_demo（重试/熔断/故障注入/健康检查）
scripts/smoke.py冒烟自检：离线可加载完整系统

一句话锚点

层1 不演出——它给的不是功能，是安全感： 改代码不慌（测试）、交付不崩（懒校验）、服务挂了有缓冲（稳定性）、加子 Agent 不动主代码（注册中心）、 未来看得懂当初（ADR）。看懂层0，就懂了晓问在做什么；看懂层1，就懂了晓问为什么这么写。

建议阅读顺序：图 A（结构）→ 表 B（动机）→ 图 C（测试原理）→ 表 D（逐文件）。逐文件精读推荐从 plugin_registry.py（注册中心）或 src/xiao_wen/agents/（子 Agent 实体契约）开始。
