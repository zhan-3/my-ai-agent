# ADR-0009：对话线程与活跃任务

- 状态：已接受（2026-08）
- 相关：ADR-0002（会话循环）、ADR-0006（Postgres 记忆）、ADR-0007（JWT 用户身份）

## 背景

现有 Web 路径令 `session_id = user_id`，把认证用户、短期对话和长期记忆压成同一维度。刷新页面后前端消息为空，后端却继续读取该用户以前的消息，形成不可见上下文。主管只有截断文本，没有未完成任务的显式状态，跳跃对话容易串话。

## 决策

在既有主管图外增加有状态对话层，借鉴 Pi 的 transcript、显式 state、turn lifecycle 和 continue 语义，但不引入无界自治循环。

1. `user_id` 只标识长期偏好、历史行程和认证主体。
2. `conversation_id` 标识前端可见的一段对话；Web 层派生用户作用域内的 `thread_id`，短期消息和轮次锁按其隔离。
3. 未完成行程保存为独立活跃任务，包含聚焦的续接文本和缺失要素；独立查询可临时打断但不覆盖任务。
4. 行程完成或用户明确取消时清除活跃任务。独立请求完成后明确提醒仍待补充的要素。
5. `session.chat()` 保持兼容：未传 `user_id` 时，`session_id` 同时作为线程和长期记忆所有者。

本 ADR 修正 ADR-0002/0006/0007 中“Web 会话维度 = 用户名”的旧语义：JWT 仍强制用户隔离，但不再等同于对话线程。

## 后果

前端必须为每个可见对话发送稳定 `conversation_id`，并可创建新对话。Postgres 增加活跃任务表；消息仍复用现有表。对话列表、跨设备恢复和多实例协调留待后续。
