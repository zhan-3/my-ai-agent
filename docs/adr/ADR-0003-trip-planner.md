# ADR-0003：行程规划深模块与事实边界

- 状态：已接受（2026-08，收敛更新）

## 决策

`trip_planner.py` 封装行程的提取、常驻城市补全、缺项检查、生成、验证、写回与展示拼装；
`agents/itinerary_agent.py` 仅负责 `collect-then-compose` 上游收集和薄适配。

编排顺序属于产品行为：常驻城市补全先于缺项检查，缺项时不调用生成模型，候选通过日期、天数
和政策证据验证后才能写回。政策不可用必须显式展示，天气失败不能用猜测填充。

票务事实不在本地维护。规划只生成 12306 官方链接、解析官方站点并校验日期，不提供车次、
时刻、余票、票价或购买结果。预算仅保留标注为“非报价、非公司政策”的住宿与餐饮规划估算，
交通金额由用户在官方页面实时确认。

## 后果

行程 Agent 不理解预算、天气、票务或验证细节；调用方只消费 `TripOutcome`。估算、政策事实和
实时事实具有不同来源与展示标签，避免把确定性计算误当成实时报价或公司标准。
