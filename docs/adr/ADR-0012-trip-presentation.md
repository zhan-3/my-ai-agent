# ADR-0012：行程呈现策略（整体结构 + 长差折叠 + 餐饮退出逐日）

- 状态：已接受（2026-08）
- 相关：ADR-0003（行程规划）、ADR-0011（行程生命周期）

## 背景

早期行程呈现采用「逐日切块」：每天一段（交通/住宿/活动/用餐），并在 prompt 里要求
「每天写一条用餐建议，结合用户偏好」。实机使用暴露三类问题：

1. **餐饮逐日是噪音**：每天重复「用餐：清淡不辣」没有信息量——餐饮偏好属于一次性提示
   （记住即可），逐日消费的是用户没要求的推荐。而「推荐每天吃什么」需要地图/POI 数据，
   当前没有接入，LLM 只能重复偏好复述，属于越界内容。
2. **长差中间日空白**：14 天出差中间 12 天用户没有具体安排，逐日列「出差/工作」这类
   泛化活动（LLM 常把 purpose 逐日重复）既重复又无信息。
3. **活动字段编造**：LLM 会编造用户没说过的活动、精确时间戳和陪同对象。

## 决策

1. **整体结构**：行程正文为 `📋 summary → 💡 安排理由 → 🚄 去程 → 🏨 住宿 → 🚄 返程 →
   📌 行程安排（每日要点一句话）`；尾部顺序为预算 → 天气（7 天窗口内）→ 空气（PM2.5 ≥ 75
   且窗口内）→ 应急 → 报销 → 政策依据。不再逐日切块。
2. **餐饮退出逐日**：不逐日写用餐；餐饮偏好只在 🏨 住宿之后提示一次
   （`🍽️ 饮食偏好：…`，有偏好才显示，来源为长期偏好 + 本轮陈述偏好去重）；
   餐饮报销标准放在预算块。**纠正此前 grilling Q4 的旧决策「用餐每天保留结合偏好」。**
3. **长差折叠**：`duration_days > 5` 时行程安排只列首日、用户明说安排了具体事项的日期和
   末日；空白中间日合并为一行（`其余 N 天：继续{purpose}` 或 `其余 N 天：无特别安排`）。
   泛化活动（`出差/工作/办公/上班/公务`，`_GENERIC_ACTIVITIES`）在展示层代码过滤，
   **不依赖 LLM 自觉留空**——即使 LLM 逐日填了「出差」，折叠逻辑照常生效。
4. **活动只写事实**：activities 只写用户明说安排 + 必要事实项（首日「抵达后入住酒店」、
   末日「返程」）；禁止精确时间戳、禁止编造陪同对象/门店名；purpose 在 summary 体现。
5. **数据与展示分离**：`trips.plan.days` 落库保持完整逐日数据（不丢信息），折叠只发生在
   展示层（`format_plan`）。前端 `parseTrip` 兼容新格式与旧 `【】` 块（折叠进 itinerary），
   `TripCard` 对 plan 来源与文本回退来源归一化渲染（`planToParsed` / `parseTrip`）。

## 后果

- `format_plan(plan, diet_pref, purpose)` 是纯展示函数，`diet_pref`/`purpose` 由调用方注入。
- LLM 的 plan_prompt 同步收紧（餐饮不逐日、长差不重复泛化活动），但展示层兜底保证
  确定性结果，不受模型波动影响。
- 前端行程卡片新增 🍽️ 行渲染；历史消息文本回退解析保持向后兼容。
- 行程归档数据（plan.days）保持逐日完整，未来若接入地图/POI 数据可在展示层扩展
  逐日内容，无需迁移存量数据。
