# ADR-0005：插件机制为加分项交付物，产品路径保持固定六 worker

插件注册中心（动态发现 / AST 渐进式披露 / 懒加载 / 热插拔演示）是课程加分项 C 的完整交付物，评分要求为"机制级"：意图识别阶段仅加载元数据、未使用的模块不加载——均由 `plugin_registry.py` + `demos/plugin_demo.py` 满足并有测试（test_plugin）。**决定：产品路径（system.app 六 worker 主管图）不接插件路由**，两者边界明确；插件的"新意图"（如 stats.py 的 差旅统计）仅作为动态发现演示存在。

## Considered Options

- **接线**：把 demo 的 manifest 驱动主管机制并入真实图（否决：会改动已验收的分类词汇表与路由，且评分要求不要求产品路径插件化）。
- **替换**：插件按六意图覆盖内置实现（否决：stats 的"差旅统计"仍无法被分类，动态发现卖点只剩"换实现"）。
- **保持机制级交付**（选）：零行为变化，README 已如实按"机制 + 四幕演示"描述。

## Consequences

- 后续评审不再重提"把插件接进主管"；产品路径的意图词汇表保持固定六类。
