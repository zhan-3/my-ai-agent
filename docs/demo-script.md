# 演示脚本（8.3 答辩演示）

> 目标：用一条故事线覆盖 3 类必演案例（行程规划 / 偏好记忆·历史记忆 / 知识问答·信息查询），
> 并顺带展示加分项（Agent 编排、SSE 流式、行程生命周期、长差折叠、确定性策略门）。
> 所有提示词均经过实机验证，按顺序照读即可。

## 演示前准备（1 分钟）

1. 启动：`docker compose up -d postgres` → 后端 8000 → 前端 5173（`pnpm --dir frontend dev:ui`）
2. 准备**全新演示账号**（记忆从零开始，偏好/历史的演示才有说服力）：
   - 前端注册 `demo` 账号（或直接复用已准备的账号）
3. 日期说明：脚本中日期是示例，演示当天**改用近 7 天内的日期**
   （天气/空气只在出发日 7 天预报窗口内查询，超窗会静默跳过，演示效果差）
4. 开场白（30 秒）：
   > 「这是企业差旅智能助手『晓问』——多 Agent 架构，一个主管 Agent 自主调度 6 个
   > 子 Agent（行程规划/偏好/历史/知识/联网/兜底），外加一个可动态注册的外部插件。
   > 下面用一个完整的出差故事演示。」

---

## 场景一：知识问答（必演①）——「先查政策」

**提示词**：

```
出差住宿标准是什么？一线城市能住多少钱？
```

**预期**：
- intent=知识问答，回答按城市分级（一线≤500/二线≤400/三线≤300/特殊地区上浮20%）
- 回答尾部带 RAG 证据来源（`policy_status=grounded` + 语料名 `01_travel_standards`）

**讲解点**：
- 政策结论**必须携带 RAG 证据**（确定性策略门，不被主管文本覆盖）
- 政策数字是「硬伤」——由代码读 RAG facts 回答，不依赖 LLM 记忆

**备选**（追问，展示"软伤"由 LLM 回答 + 证据延续）：

```
报销要在出差结束后多久内提交？订票一般要提前几天？
```

## 场景二：行程规划（必演②）——「规划一趟出差」

**提示词**（含偏好注入，一石二鸟）：

```
帮我规划行程：下周三从北京去杭州出差拜访客户，待2晚，高铁往返
```

**预期**：
- intent=行程规划，**一次生成**完整行程（不追问）：3 天逐日安排、高铁（带
  「以晓问商旅平台实时查询为准」票务边界话术）、住宿按政策标准（杭州二线≤400）、
  预算块、目的地天气提醒、报销时限提醒、政策依据
- 若账号已有偏好（不吃辣/喜静），理由区会自动带上
- 前端显示**行程卡片**（结构化渲染，非纯文本）

**讲解点**（挑 2-3 个即可，别贪多）：
- 「待2晚 = 3 天」由**代码层确定性归一化**，不依赖 LLM 自觉（这是实机测试修出来的 bug）
- 票务边界：不查车次/余票/不代购票，只建议交通方式
- 住宿金额、预算按 RAG 政策标准估算，标注「非报价」

**加分项·长差折叠**（时间允许才演示，日期改为 7 天内更长的区间）：

```
帮我规划行程：下周一从成都去广州出差参加展会，待6晚
```

预期：中间空白停留日折叠成「其余 N 天」一行，不是逐日重复写「出差/工作」。

**加分项·改期（生命周期）**：

```
把刚才杭州的行程改到下周五一早出发
```

预期：更新同一条行程记录（`upcoming` 状态，改期不新建）。

## 场景三：偏好记忆（必演②）——「让系统记住我」

**先点「新对话」**（展示 conversation_id 隔离：新对话不继承旧 transcript，但长期记忆全局生效）

**提示词**：

```
我不吃辣，住宿喜欢安静，常住成都
```

**预期**：
- intent=偏好记录，回答「已记住：餐饮偏好【不吃辣】、住宿偏好【喜欢安静】、
  常驻城市【成都】，下次规划自动生效」
- 前端**记忆侧栏**即时出现新条目

**验证（关键一步，同一新对话内继续）**：

```
帮我规划行程：下周五从成都去西安开会，待1晚，飞机往返
```

**预期**：
- **出发城市自动取常驻城市「成都」**（用户没说出发地也不追问）
- 理由区出现「用户不吃辣、喜欢安静」→ 住宿按偏好选安静连锁酒店、餐饮避开辣味
- 与场景二对比：**同一套提示流程，第二次自动带上个人化设置**——这就是记忆的价值

**讲解点**：
- 长期记忆（偏好/行程）按**用户**全局存储，跨对话生效；工具 transcript 按对话隔离
- 常驻城市补全**先于**缺项检查：用户没说出发地但有记忆 → 不算缺项，直接补

## 场景四：历史记忆（必演②）——「回顾我的出差档案」

**再点「新对话」**

**提示词**：

```
我最近有哪些行程？杭州那次出差安排是什么？
```

**预期**：
- intent=历史查询，列出历史行程（规划中/待出发/已完成/已取消四态）
- 前端显示历史卡片，可点「继续对话/改期/取消」

**加分项·取消**（展示生命周期收尾）：

```
把成都那次出差取消吧
```

预期：状态变为「已取消」（`cancelled`，保留记录不删除）。

**加分项·差旅画像**：

```
我出差花销大概什么水平？去过哪些城市？
```

预期：intent=统计（动态注册的外部插件 `plugins/stats.py` 提供），返回差旅画像。

## 场景五：信息查询（必演③）——「实时数据」

**提示词 A·天气**：

```
杭州明天天气怎么样？
```

**预期**：联网查询，返回温度/体感/降水概率/紫外线/风速；前端 SSE **打字机流式**输出。
**讲解点**：天气失败显式呈现、不编造（可讲：免费 API 不可用时系统说「查询失败」而不是编数据）。

**提示词 B·汇率（金额问法）**：

```
100美元等于多少人民币？
```

**预期**：联网查询，返回「1 USD ≈ 6.75 CNY，100美元约 675 元」。
**讲解点**：金额问法（不说「汇率」二字）也能正确触发汇率工具——这是实机测试修复的门禁漏判。

**提示词 C·空气质量**：

```
北京现在空气质量怎么样？
```

**预期**：PM2.5/PM10 数值 + 污染等级提醒（≥75 才提醒）。

## 收尾话术（30 秒）

> 「刚才完整演示了：政策知识问答带 RAG 证据 → 行程规划自动应用个人偏好 →
> 跨对话的偏好与历史记忆 → 实时天气/汇率查询。底层是主管 Agent 的自主编排
> （decide→调子 Agent→观察→再决策），外加确定性策略门兜底——LLM 再聪明，
> 票务边界、政策证据、日期校验这些硬规则都不会被绕过。
> 质量上：264 个确定性后端测试 + 28 个真实 LLM 回归用例 + 42 个前端测试。」

## 兜底预案（演示翻车怎么办）

| 现象 | 处理 |
|---|---|
| 行程突然进入追问（缺要素） | 照系统提示补一句「对，就是那样」/「从北京出发」，顺势展示澄清机制也是亮点 |
| 天气/汇率查询失败（免费 API 抖动） | 直接说「看，外部服务不可用时系统**显式提示失败**而不编造数据」——也是设计点 |
| 演示账号记忆不干净 | 用注册新账号重来（偏好/历史场景最怕脏数据） |
| 生成太慢（LLM 波动） | 讲稿先讲架构/能力矩阵，让回复在后台跑 |
