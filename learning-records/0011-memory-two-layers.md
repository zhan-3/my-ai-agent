# LR-0011 · 两层记忆：短期 + 长期（加分项 A）

**日期**：2026-08-10（第十课后）
**主题**：记忆分层——短期（最近 N 轮对话）+ 长期（偏好/历史/常驻城市），含追加/覆盖区分
**背景**：用户主动提出「先完善 memory 短期和长期」，并给了 LangChain 官方 memory 文档链接（docs.langchain.com/oss/python/concepts/memory）——首次主动给官方文档，验证意识增强

## 官方概念对照（读文档所得）

- 短期记忆 = thread-scoped（单会话消息历史），LangGraph 官方用 **checkpointer** 持久化 state + thread 隔离恢复
- 长期记忆 = 跨会话共享，官方用 **store**（namespace/key 组织 JSON 文档 + 语义搜索）；两种管理方式：Profile（单文档持续更新）vs Collection（窄记忆集合）
- **hot path**：在 agent 运行时内创建记忆的权衡——实时但增加延迟/复杂度/多任务负担；可 background 异步写
- 官方明确建议：避免完整长历史全塞上下文（超窗口/过时干扰/变慢变贵）→ 裁剪、遗忘
- 该文档未提 MemorySaver，核心机制是 checkpointer + thread

## 我们的实现（作业尺度）

1. **短期记忆**：memory_store 加 messages 表；demo 主循环每轮 invoke 前 `format_recent_messages(6)` 注入意图识别 + web 节点上下文（指代消解）；invoke 后 add_message 写回（hot path）
2. **长期记忆升级**：
   - `add_or_update_preference(category, content, is_update)`：is_update=True 替换同类别旧条目（追加/覆盖区分，加分项）
   - 偏好类别加「常驻城市」；`get_home_city()`；行程 worker 出发城市缺失时自动补全（「别再傻问」）
   - `get_common_destinations()` 从历史行程统计常用目的地（出差习惯）
3. **hot path 权衡**：注入截断最近 6 轮，避免全量历史
