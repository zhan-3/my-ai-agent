# LR-0013 · 调度优化：并行执行（加分项 B 完成）

**日期**：2026-08-10（第十二课）
**主题**：Send API 并行调度——一句话多请求 → 拆分子任务 → 并行派发 → 汇总
**背景**：用户选「先调度优化」；加分项 B 四种做法中动态路由/先收集信息已有，补「同优先级任务并行执行」

## 关键决策与事实

1. **机制**：LangGraph Send API（fan-out/fan-in）——条件边函数返回 `[Send(node, payload)]` 列表，每个 Send 一个独立并行分支，全部完成后 fan-in 到 merge
2. **多意图拆分**：意图识别 schema 加 `subtasks: list[SubTask]`（intent + text）；提示词用「顺便/还有/以及」等连接词启发；拆不准回退单意图（空数组走原路由，不破坏已验证功能）
3. **并行写冲突解决**：并行 worker 输出到 `collected: Annotated[list, operator.add]`（归约器拼接），不直接写 answer（多个 worker 写同一 key 会覆盖丢数据）
4. **复用不重写**：make_parallel(worker) 包装原 worker——只换 user_input，六个 worker 节点零改动（模块化收益：调度增强不动 worker）
5. **踩坑两个**：
   - Send 只能由**条件边函数**返回（放进普通节点报 `Expected dict, got [Send...]`）
   - 条件边 path_map 只含字符串分支，Send 列表无需进映射
   - 另：add_node 函数名 vs 显式节点名不一致导致 compile 报 unknown node（中文节点名 + path_map 一一对应修复）
