# LR-0010 · 组装完整系统 v3（六个 worker 全部做实）

**日期**：2026-08-10（第九课后）
**主题**：多 Agent 系统总装——意图主管 + 六个真 worker 端到端
**背景**：基础项 6 项已全（意图/调度/要素提取/知识RAG/行程/联网），第十课把各课成果组装成可演示的完整系统

## 关键决策与事实

1. **总装方式**：`homework/0010_system.py` 复制 0006 骨架（意图主管 prompt + 六个 worker 拓扑），仅把两个桩替换为真实现——knowledge 用 importlib 加载 0008（rag.knowledge_qa）、web 加载 0009（web.app 图 + SYSTEM）
2. **接口契约**：所有 worker 统一「输入 state → 输出 {"answer": str}」，这是多模块组合的前提
3. **嵌套 agent**：web 节点内部是另一个完整的 LangGraph 图（0009 的 ToolNode ReAct）——「一个图里嵌一个图」是真实多 Agent 的常态（编排者-工人 + 工人内部 ReAct）
4. **记忆闭环完整**：偏好写入（2026-08-10 17:40）→ 行程生成读偏好注入 → 行程写回 → 历史查询可读

## 实测（6/6 端到端）

| 案例 | 意图路由 | 结果 |
|---|---|---|
| 我不吃辣，住宿喜欢安静 | 偏好记录 ✅ | 写入记忆 |
| 10月8日广州→北京开会4天 | 行程规划 ✅ | 自动排全季（西站店）+ 每餐不辣 + 完整4天行程 + 写回历史 |

| 这个暑假去哪里玩 | 其他 ✅ | 边界拒绝，说明服务范围 |

**亮点**：偏好「不吃辣」渗透进行程每一餐（清汤面/避免辣味蘸料）——记忆 → 个性化生成的完整链路实证。
**小瑕疵（教学点）**：历史查询出现「待定 待定→待定，0天」占位记录——0006 测试残留，记忆持久化的证明；真实产品要区分测试/生产库。

## 追加：基础项 E 补齐（缺失提示 + 安排理由）

用户追问「基础项 ABCDE 都实现了吗」→ 翻作业文档逐条核对：A/B/C/D 全 ✅，E（结果可读性）两处缺口：①缺失信息提示（日期待定时应问用户而非生成占位行程）②安排理由（作业明确列了"安排理由（差旅政策、报销规则、交通拥堵、天气等）"）。用户说"补上"。

改动（0005/0006/0010 三处同步）：
1. ItineraryPlan 加 reasons: list[str]；plan_prompt 要求生成安排理由（政策/偏好/交通合理性）
2. format_plan 在摘要后展示「💡 安排理由」
3. 新增 _missing(req) 缺失检查：目的/出发城市、日期待定、天数≤0 → 返回提示不硬生成（不调生成模型、不写回记忆）
