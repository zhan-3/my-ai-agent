Lesson 13 / 工程质量

mypy 类型检查：从 22 个警告到 0，还抓到一个真 Bug

作业评分点 7.4「工程质量」要求代码可维护。这课用 mypy 扫全项目——关键是学会区分真问题和库类型标注噪音，别为了消警告乱改代码。

第一课：类型检查的价值 = 抓回归

扫描 11 个文件，22 个警告。最有价值的发现不是警告本身，而是一个真 Bug：

# homework/0006_memory.py
from memory_store import (add_preference, ...)   # ❌ 此函数早已改名！

# memory_store 里它已变成：
def add_or_update_preference(category, content, is_update=False): ...

教训：改名后必须全局搜引用 + 回归验证

第十一课把 add_preference 升级成 add_or_update_preference（加 is_update），但 0006 还在 import 旧名字——一跑就会 ImportError。为什么没被发现？因为改名后再没跑过 0006。mypy 一跑就报 Module "memory_store" has no attribute "add_preference"。改名/重构后，全局搜索旧名字 + 重新跑所有引用它的测试——这是类型检查最值钱的地方。

22 个警告分三类

类别数量处理
真 Bug（0006 旧函数名）1改 import + 调用，回归验证 ✅
防御性改进：raise 可能为 None、importlib spec 可能为 None、结构化输出结果收窄为模型实例4if spec is None: raise ImportError、assert isinstance(r, PreferenceRecord)、raise RuntimeError(...) from last
变量注解：para = [] → para: list[str] = []6补注解（真实小改进）
库噪音：LangGraph invoke 重载过严（×7）、jieba 无类型 stub8+配置级关闭 call-overload（注明理由）；jieba 单处 ignore

噪音 vs 真问题：怎么判断

# 噪音示例：LangGraph Pregel.invoke 的重载对「部分键 State 输入」过严
# demo 合法地只传部分 state 键（recent/subtasks 由节点补），mypy 却要求全量
app.invoke({"messages": [...], "user_input": t, "recent": recent})
# → 运行时完全正常。配置级关闭，不逐处 ignore（避免代码噪音）：
# pyproject.toml [tool.mypy]
# disable_error_code = ["call-overload"]   # 注释写明理由

判断原则

① 警告指向「运行时会崩/可能崩」→ 真问题，改代码。
② 警告指向「库自己的类型标注缺陷」→ 噪音，配置级关闭或单处 ignore，并写明理由。
③ 只为了消警告而加 # type: ignore 不写理由 → 掩盖问题，禁止。
