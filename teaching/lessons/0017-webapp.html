Lesson 17 / 可视化界面

把终端里的 Agent 变成网页产品

加分项 F：写个可访问的 Web 界面，产品化项目，让回答不只停留在终端。这课用 FastAPI + 原生 HTML/JS 把 0010 的完整系统包成聊天产品——零构建、离线可用、自动 /docs。

架构：后端复用 0010，一行 Agent 逻辑不重写

浏览器 ──→ GET  /           前端页面（单文件 HTML + JS）
        ──→ POST /api/chat   {user_input, session_id}
              └─→ 0010 的完整主管图（六 worker）
                  ├─ 短期记忆注入（invoke 前 format_recent_messages(6)）
                  ├─ 写回（invoke 后 add_message ×2，hot path）
                  └─ {answer, intent, reason}
        ──→ GET  /healthz   健康检查（配合加分项 D）
        ──→ GET  /docs      FastAPI 自动交互式文档

为什么选 FastAPI + 原生 JS

方案代价结论
React/Vue 前端node 构建链、离线不可用✗ 过重
Streamlit/Gradio样式受限、演示感弱△ 可用但不像产品
FastAPI + 原生 HTML/JS零构建、离线、自动 /docs✓ 正好

FastAPI 自带交互式 API 文档（/docs）——演示时一开就有，还能讲「自动文档」这个点。

记忆闭环：和 0010 demo 完全一致

Web 界面不是新写一个系统，而是把 demo 的对话循环搬进 API：

# 0010 demo（终端）                       # 0014 webapp（Web）
recent = format_recent_messages(6)  →     r = app_graph.invoke({...})
r = app.invoke({...})                →     add_message("user", text)
add_message("user", t)               →     add_message("assistant", r["answer"])
add_message("assistant", r["answer"])

所以「那上海呢」的指代消解、常驻城市补全，在网页上原样生效——因为逻辑没动，只换了壳。

前端三件小事

  1. 建议 chips：预设 5 个演示问题，点一下就发——演示时不用打字
  2. 打字机效果：逐字渲染回答（setTimeout 8ms/字），有「在思考」的产品感
  3. XSS 转义：esc() 把 <>& 转义再进 innerHTML——任何用户输入都渲染成文本

真实工程课：地理编码服务挂了怎么办

Web 联调时发现 nominatim 挂了（curl 空响应）→ 天气查询全部失败。这不是 F 的问题，是 0009 的隐患暴露了。解法——多级降级：

_geocode(city):
    if city in CITY_COORDS:      # ① 本地内置中国差旅城市表（零依赖、永远可用）
        return CITY_COORDS[city]
    geo = _get_json(nominatim)   # ② 未收录城市才走外部 API（兜底）

20 个中国差旅城市经纬度写死进代码——比任何外部 API 都快且稳，还免限流。这就是稳定性思维：能本地化的绝不依赖网络。
