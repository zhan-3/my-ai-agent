Lesson 6 / 记忆（基础项）

记忆：让系统「记住你」——偏好落库与历史查询

学完这课，你的系统会记住用户偏好、在下次排行程时用上它、还能回答历史行程。

和你的使命的关系

作业基础项里有「偏好记录」「记忆查询」两个角色。这课把它们做实，并让行程规划读取记忆——你的系统第一次有「连续性」：不是每次从零开始，而是越用越懂你。这也是作业演示时最有记忆点的场景。

记忆闭环

  偏好记录(worker) ──写入──▶ memory.json ◀──写入── 行程规划(worker)
        ▲                        │                        ▲
        │                    读取(历史查询)                │
  用户说偏好              用户问历史行程               生成前读偏好
        │                        │                        │
        └────────────────────────┴────────────────────────┘
                    存储层（memory_store 模块）

三个工人共享同一个存储层：preference 写入偏好，itinerary 生成前读偏好、生成后写行程，history 读行程。存储层和业务解耦——先文件、后数据库，业务代码不用改。

JSON 文件存储，数据在 data/memory.json（已进 .gitignore）。诚实声明：单机演示够用；真实产品要 user_id 隔离 + 数据库/向量库（偏好查询可能是语义检索）。写作业文档时把这个「为什么先文件」讲清楚，是加分点。

② 行程规划「读取偏好」：上下文注入

def itinerary(state):
    req = extract_model.invoke({"input": state["user_input"]})
    prefs = get_preferences()                       # ← 读记忆
    prefs_text = "；".join(f"{p['category']}:{p['content']}" for p in prefs) or "无"
    plan = plan_model.invoke({
        "trip_json": req.model_dump_json(),
        "prefs": prefs_text,                        # ← 拼进提示词
        "user_input": state["user_input"],
    })
    add_itinerary(req.model_dump(), plan.summary)   # ← 行程写回记忆
    return {"answer": format_plan(plan)}

把历史偏好拼成一行文本塞进生成阶段的提示词。实测效果：记住「喜欢住全季」后，新行程自动排了全季酒店（西湖店），总结里还写了「符合您的偏好」。这就是记忆的价值——不换模型、不加参数，只靠注入上下文。

③ 本课踩到的坑：上下文一变，输出结构漂了

加了偏好上下文后，模型「更卖力」，把 transport/hotel/activities 输出成了嵌套对象（{"from":…, "mode":…}），而 schema 要字符串 → Pydantic 校验直接炸。json_mode 不锁结构，模型发挥越自由，结构越容易漂。对策：提示词把每个字段的形状钉死，还给了完整示例。记住这个规律：上下文一变，就要重新验证结构化输出。
