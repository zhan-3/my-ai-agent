Lesson 9 / 联网查询（基础项）

让 Agent 学会用工具：ToolNode 与 ReAct 循环

差旅助手要查天气、查汇率——这些数据不在文档里、不在模型脑子里，只能实时去取。这课让 LLM 学会「调用工具」，也是你的最后一个基础项 worker。

和你的使命的关系

「工具」是 Agent 区别于聊天机器人的核心能力：模型无法预测的事实（天气/汇率/航班），只能靠工具实时获取。这课的机制（工具定义 → 挂载 → 执行循环）在真实产品里用来接航班查询、酒店预订、打车叫单等一切外部系统。

为什么要「工具」？

前面课程的 LLM 只会「想」（生成文本）。但有些信息它不可能知道：
「北京今天多少度？」——训练数据截止于某个日期，今天是实时事实。
「1 美元等于多少人民币？」——汇率每分钟在变。

所以要让 LLM 调用外部函数去取真数据。这就是工具（Tool / Function Calling）。

三步接一个工具

# ① 定义工具：@tool 把普通函数变成工具
#    docstring 是给 LLM 看的「使用说明书」——写清参数含义
@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气。city：城市名，如「北京」「上海」"""
    ...调用天气 API，返回文本...

# ② 挂载：把工具清单绑定给 LLM，LLM 回答时自主决定是否调用
llm_with_tools = llm.bind_tools([get_weather, get_currency_rate])

# ③ 执行：ToolNode 是 langgraph 现成的「工具执行节点」
tool_node = ToolNode([get_weather, get_currency_rate])

图结构：ReAct 循环

       ┌────────────────────────────┐
       │                            ▼
   entry → agent(LLM+工具) ──条件边──→ tools(ToolNode)
                 │                    │
                 │ 无 tool_calls       │ 执行完把结果写回消息
                 ▼                    │
                END ◄─────────────────┘（回到 agent 再判断）

条件边逻辑：最后一条消息有 tool_calls → 去 tools；否则 → END

这个「思考 → 调工具 → 看结果 → 再思考」的循环叫 ReAct 循环。实测 4/4：天气、汇率都正确触发工具拿真数据；负例（报销时限）正确识别「不需要工具」直接结束。

工具调用的三要素（deepseek-v4-flash 实测）

要素说明我们这课的实证
工具清单bind_tools 告诉 LLM「你能用这些」天气+汇率两个工具
参数 schema函数签名自动生成 JSON SchemaLLM 自动填 city="北京"、from/to=USD/CNY
执行结果回填ToolNode 把结果作为 tool 消息写回天气/汇率真数据 → LLM 再组织回答

回忆能力矩阵（LR-0004）：v4-flash 是 tools+auto ✅ / 强制 tool_choice ❌——所以让 LLM「自主决定」没问题，但别强求它「必须调某个工具」。

诚实声明

① 用的是免费公开 API：天气 open-meteo（无需 key）、汇率 open.er-api.com——真实产品会用付费聚合天气服务（和风、高德）并接航班/酒店/打车工具
② 工具出错时我们返回了错误文本（LLM 会转述）——真实产品要有重试/降级策略
③ 当前只查「当前天气」，没有未来预报、没有目的地推荐（后续可加）
