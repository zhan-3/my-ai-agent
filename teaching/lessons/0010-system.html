Lesson 10 / 系统总装

把六个 Agent 装成一个系统

前面九课你各做了一个 worker。这课把它们「总装」成完整系统 v3——意图主管 + 六个真 worker，端到端跑通作业要求的三类演示案例。

和你的使命的关系

多 Agent 系统的组装不是「把代码粘一起」，而是模块组合 + 接口对齐。这课演示真实工程的总装方式：每个 worker 是独立模块（前面各课已各自验证），总装文件只做「导入 + 挂图」。这是你以后独立搭多 Agent 系统会反复用到的模式。

v3 系统架构

用户输入
   │
   ▼
classify_intent（LLM 主管：六分类，json_mode）
   │  条件边：按 intent 路由
   ├─→ 行程规划：要素提取 → 行程生成（读偏好→写回历史）
   ├─→ 偏好记录：提取偏好 → 写入记忆
   ├─→ 历史查询：读记忆 → 返回
   ├─→ 知识问答：向量检索 RAG（embedding + chromadb）
   ├─→ 联网查询：ToolNode ReAct（天气/汇率/空气质量）
   └─→ 其他：产品边界兜底

和 v2（第六课）相比，只换了两个桩为真实现：knowledge_stub → rag.knowledge_qa()（第八课）、web_stub → web.app（第九课）。拓扑没变——骨架稳定，worker 渐进做实，这就是「先桩后实」策略的回报。

总装的三个要点

# ① 独立模块：每个 worker 是独立文件（数字开头不能 import，用 importlib 加载）
def _load(name, path):
    spec = importlib.util.spec_from_file_location(name, path)
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod
rag = _load("rag_v3", "homework/0008_rag_vector.py")
web = _load("web_v3", "homework/0009_web.py")

# ② 接口对齐：各 worker 统一「输入 state → 输出 {"answer": str}」契约
def knowledge(state):
    return {"answer": rag.knowledge_qa(state["user_input"])}
def web_node(state):
    result = web.app.invoke({"messages": [web.SYSTEM, ("human", state["user_input"])]})
    return {"answer": result["messages"][-1].content}

演示结果（作业三类案例）

案例输入系统表现
① 记忆闭环「我不吃辣，住宿喜欢安静」→「10月8日从广州去北京开会4天」偏好先写入 → 行程自动排全季（安静）+ 每餐不辣 → 行程写回历史
② 知识问答「出差住宿标准是什么？」向量检索命中差旅标准文档，一线500/二线400/三线300+连锁建议
③ 联网查询「北京今天天气怎么样？」ToolNode 调真实天气 API：晴 32.2°C
+ 边界「这个暑假去哪里玩」正确归「其他」并说明服务范围

演示中看到的数据残留——这是教学点

历史查询里出现了「待定 待定→待定，0天」的占位记录——那是之前测试 0006 时留下的。记忆是持久化的，测试会留痕迹。真实产品要区分测试库/生产库，或给测试数据加标记。这也证明：记忆闭环真的写盘了。

基础项 E 补齐（缺失提示 + 安排理由）

作业要求输出含「缺失信息提示」和「安排理由」，v3 初始版有两处缺口，本课补齐：

# ① 缺失信息检查：要素不全不硬生成，先问用户补（放在行程 worker 内）
def _missing(req):
    miss = []
    if 无目的城市: miss.append("目的城市")
    if 无出发城市: miss.append("出发城市")
    if 日期待定:   miss.append("出发日期")
    if 天数<=0:    miss.append("出差天数")
    return miss
# 命中缺失 → 返回提示（不再调生成模型、不写回记忆）

# ② 安排理由：生成 schema 加 reasons 字段，提示词要求解释"为什么这么排"
# 实测输出：💡 安排理由：
#   · 住宿按中等预算安排，全季酒店符合差旅标准
#   · 考虑你不吃辣的偏好，所有用餐均选择清淡不辣餐厅
#   · 最后一天返程，避免额外住宿费用

验证：①「帮我安排出差行程」→ 列出缺的 4 项；②「下周去杭州出差」→ 只提示缺的 3 项（杭州被正确识别为目的城市，不误报）；③完整行程 → 5 条安排理由。基础项 A-E 至此全绿 ✅
