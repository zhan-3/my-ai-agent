为什么需要熔断（不只是重试）

上游挂了时，重试会让每个请求都撞墙（又慢又花钱）。熔断器给系统一个「短期记忆」：连续失败 N 次就 open，后续请求直接拒绝、零耗时；过恢复期进入 half_open 放一个试探请求，成功则复位。

class CircuitBreaker:
    @property
    def is_open(self):
        if self.state == "open" and 超时了:
            self.state = "half_open"   # 半开试探
        return self.state == "open"
    def record_success(self): self.failures = 0; self.state = "closed"
    def record_failure(self):
        self.failures += 1
        if self.state == "half_open" or self.failures >= 阈值:
            self.state = "open"

实测：第 4 次调用 熔断已打开：拒绝调用（0ms）——之前每次都要撞上游，之后零耗时拒绝。

异常兜底：崩 vs 降级的差别

def safe_call(fn, fallback="⚠️ 服务暂时不可用，请稍后再试", *args, **kwargs):
    try:
        return fn(*args, **kwargs)
    except Exception as e:
        logger.error("异常兜底触发：%r 失败：%s", fn, e)
        return fallback      # 用户看到友好文案，而不是 traceback

一个关键细节：monkeypatch base.llm 不生效——因为 intent_model = prompt | llm.with_structured_output(...) 在构造时就把 llm 捕获进链路了。要替换必须重建模型链。这正说明：稳定性层要包在调用点（节点函数）外面，而不是指望内部依赖能换。
