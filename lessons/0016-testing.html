测试数据隔离：绝不碰真实记忆

记忆测试如果读写 data/memory.json，跑完测试你的真实记忆就没了。conftest 里用 autouse fixture 把 MEMORY_PATH 指到 pytest 的 tmp_path：

@pytest.fixture(autouse=True)
def _isolate_memory(tmp_path, monkeypatch):
    import memory_store
    monkeypatch.setattr(memory_store, "MEMORY_PATH", tmp_path / "memory.json")
    yield

monkeypatch 自动在测试后还原——这是 pytest 的隔离三件套（tmp_path / monkeypatch / fixture）。

参数化：一份用例表，批量跑

CASES = [
    ("10月8日去北京开会4天", "行程规划"),
    ...
    ("我想去三亚度假两周", "其他"),      # 产品边界：个人休闲 → 其他
]

@pytest.mark.parametrize("text,expected", CASES)
def test_intent_classification(text, expected):
    r = _sys.intent_model.invoke({"recent": "", "input": text})
    assert r.intent == expected

7 个用例一个参数列表搞定；失败时 pytest 精确告诉你「哪个输入 → 期望什么 → 实际得到什么」。

最有心机的测试：证明「零加载」

插件注册中心的渐进式披露（AST 不执行代码）怎么测？写一个「加载即爆炸」的假插件：如果 discover 执行了它，测试当场炸——而 discover 能读到它的元数据，说明 AST 解析正常：

(tmp_path / "boom.py").write_text(
    "raise RuntimeError('discover 不应该执行插件代码！')\n"
    "INTENT = '爆炸'\nDESCRIPTION = 'x'\n", encoding="utf-8")
found = reg.discover()
assert found[0]["INTENT"] == "爆炸"   # 读到元数据，但代码从未执行 ✓

测试踩坑：真实 API 约束 vs 测试假设（3 个）

坑真相
TripRequest(**base) 校验失败pydantic 字段是必填的（hotel_pref/budget_pref 没有默认值）——读模型定义，别猜
断言 rec["is_update"] 失败add_or_update_preference 返回的 dict 没有 is_update 键——验证行为用 get_preferences 查询，别假设返回结构
熔断 sleep 后 state 没变is_open 是 @property——访问它才触发状态迁移（惰性）。sleep 后要先访问再断言

这 3 个坑本身就是教训：测试的假设必须来自真实接口，不是你以为的接口。
