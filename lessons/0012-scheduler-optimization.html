做法状态

核心机制：Send API（动态并行）

LangGraph 串行：一个节点跑完 → 下一个。要并行，得让一个节点动态生成多个分支——这就是 Send：条件边函数返回 [Send(节点, payload), Send(节点, payload), ...]，LangGraph 为每个 Send 开一个独立执行分支（fan-out），全部跑完再汇合（fan-in）。

# ① 条件边函数：多意图 → Send 列表；单意图 → 字符串路由
def dispatch(state):
    subs = state.get("subtasks")
    if subs:
        return [Send(f"p_{s['intent']}", {"current_task": s}) for s in subs]
    return state["intent"]

# ② 每个子任务一个并行包装节点（复用原 worker！只换 user_input）
def make_parallel(worker):
    def node(state):
        sub = state["current_task"]
        out = worker({**state, "user_input": sub["text"]})
        return {"collected": [{"intent": sub["intent"], "answer": out["answer"]}]}
    return node

# ③ collected 用归约器（operator.add）→ 并行结果自动拼接不互相覆盖
class State(TypedDict):
    ...
    collected: Annotated[list[dict], operator.add]

# ④ 组装：p_* 全部 → merge（fan-in）汇总
for intent in WORKERS:
    graph.add_edge(f"p_{intent}", "merge")

踩过的两个坑

① Send 只能由条件边函数返回——把它放进普通节点会报 Expected dict, got [Send...]。② 条件边的路径映射（path_map）只包含字符串分支，Send 列表不需要也不应该出现在映射里。

意图识别升级：多意图拆分

并行之前，主管要先认出"这一句话里有几个活"。意图识别输出加 subtasks 数组（每项：intent + 原文），提示词用「顺便/还有/以及」等连接词作启发式。拆不准时回退单意图（subtasks 为空走原路由），保证不破坏已验证功能。
