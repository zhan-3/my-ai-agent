Lesson 11 / 记忆分层

短期记忆 + 长期记忆，各司其职

上一课你的系统已经有「偏好+历史行程」记忆，但那只是长期记忆。这课补上**短期记忆（最近 N 轮对话）**，并把长期记忆升级出**追加/覆盖区分**和**常驻城市**——正好是作业加分项 A 的全部要求。

先对齐官方概念（LangChain Memory 文档）

官方概念是什么我们的实现
短期记忆（thread-scoped）单个会话内的消息历史，随会话走memory_store 的 messages，最近 6 轮，每轮 invoke 前注入
长期记忆（跨会话共享）偏好/历史/习惯，任何会话可召回memory_store 的 preferences / itineraries / 常驻城市
checkpointerLangGraph 官方：把 state（含消息）持久化到数据库，线程随时恢复我们手写 JSON 版（教学简化；真实产品用 checkpointer）
store官方长期记忆：namespace/key 组织 JSON 文档 + 语义搜索JSON 文件 + 简单查询（真实产品用 store + 向量检索）

官方文档地址：docs.langchain.com/oss/python/concepts/memory

短期记忆：注入什么、注入多少（hot path）

# 每轮对话流程（demo 主循环）：
# ① 检索：从记忆取最近 6 轮 → 注入意图识别（理解「那上海呢」）
recent = format_recent_messages(6)
r = app.invoke({"messages": [("human", t)], "user_input": t, "recent": recent})
# ② 写入：本轮对话存进短期记忆（hot path 写入）
add_message("user", t)
add_message("assistant", r["answer"])

官方提醒：别把完整长历史全塞进上下文

长对话会：①超出上下文窗口；②过时/离题内容干扰判断；③变慢、更贵。所以短期记忆**截断最近 N 轮**再注入。这是「hot path」的核心权衡——记忆检索/写入都在推理路径上，每一步都有延迟和 token 成本。
